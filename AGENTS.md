# AGENTS.md

Notes for AI agents working on the `nixos-parts` repository.

## Repository overview

`nixos-parts` is a reusable dendritic `flake-parts` flake that exposes
NixOS and Home Manager modules. It is consumed by external flakes that
import `nixosModules.biapy` / `nixosModules.default` /
`homeModules.biapy` / `homeModules.default`.

## Layout

- `modules/nixos/default.nix` — flake-parts entry; defines
  `biapyNixOSModule` and `biapyUsersNixOSModule` and wires
  `import-tree` over `modules/nixos/_biapy` and
  `modules/nixos/_biapy_users`.
- `modules/nixos/_biapy/` — NixOS feature modules, organised by topic
  (hardware, networking, services, system, programs, security, etc.).
  Every `.nix` file in this tree is auto-imported.
- `modules/nixos/_biapy/private/` — internal-only NixOS options that
  downstream flakes are expected to set before the module system
  evaluates. They live under `private/` to make the public/private
  split explicit. Examples: `biapy.defaultUser`, `biapy.normalUsers`.
- `modules/nixos/_biapy_users/` — separate module set
  (`biapyUsersNixOSModule`) that declares user identities through
  `biapy.users.users` and the per-user GECOS `identity` submodule.
  On Linux, `isNormalUser = true; createHome = true;` are applied
  via `mkDefault` (`modules/nixos/_biapy_users/linux.nix:23`).
- `modules/home/_biapy/` — Home Manager modules, auto-imported.
- `packages/` — overlay packages (sk*, batline, flyline, quien, …).
- `flake.nix` — generated by `nix run .#write-flake`; do not edit
  manually.

## Conventions

- Files declare `lib` destructuring at the top of the `let` block,
  e.g. `inherit (lib.options) mkOption;` and
  `inherit (lib.types) listOf str;`. Match this style.
- Options that depend on other config values use a `default` that
  reads `config.…` directly, with no `defaultText`. Use the existing
  `defaultUser.nix` / `normalUsers.nix` files as a template.
- For private option defaults derived from `config.users.users`,
  prefer:
  ```nix
  attrNames (filterAttrs (_: u: u.isNormalUser) config.users.users)
  ```
- Hardware-per-user group assignment pattern:
  ```nix
  users.users = lib.genAttrs config.biapy.normalUsers (_: {
    extraGroups = [ "video" ];
  });
  ```
  See `modules/nixos/_biapy/hardware/backlight.nix:58`.
- Public user identity is configured through `biapy.users.users`,
  not through `users.users` directly.

## Tooling

- Format: `mise run fmt` (alias `mise fmt`, also `nix fmt` via the
  flake). The formatter is `nixfmt` / `nixfmt-tree` from
  `github:Mic92/nixfmt-rs` (see `mise.toml`).
- Lint/typecheck: `nix flake check`.
- Regen `flake.nix`: `nix run .#write-flake` (alias `wf`).
- Tests live under `checks.x86_64-linux.nix-unit` and are defined
  inline as nix expressions; see `modules/nixos/default.nix` for an
  example of an inline `tests` block on a flake-parts option.
- LSP for `.nix`: `nil` (configured in `opencode.jsonc`).
- Local skills for repo-specific workflows live under
  `.agents/skills/` (`file-search`, `nix`, `nix-flake`). Skills in
  `~/.agents/skills/` are user-global.

## Gortex MCP

The repo is indexed by Gortex (`opencode.jsonc`). The MCP server is
mandatory in this environment — prefer `mcp__gortex__*` tools for
search/read/trace and reserve host Read/Grep/Glob/Bash for cases
where Gortex performance or integration is actually bad. Before
mutating a file, call `change(operation:"impact")`; for signature
changes also `change(operation:"verify")`. After editing, run
`change(operation:"detect")` and follow up with `tests` / `guards` /
`contract` using the returned symbol IDs.

## Pre-commit / hooks

`mise.toml` pins `prek`; keep its hook list up to date when adding
new linters or formatters.
